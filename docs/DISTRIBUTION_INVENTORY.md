# Distribution inventory

Revision 10 · 2026-09-30 · Recorded by session W0 at M0.2 under D15 and D18; amended by session W2A at M1.8 under D62 and D68, after the first tarball inspection, by session W3A at M2 under D76, for the preview bundles and the editor's tool pages, by session W3C at M4.1 under D100, for the vendored page-turn engine, by session W4 at M4.2–M4.8 under D108, D109 and D119, for the comic's `dist/`, its bundles and its sample, by session W5B at M5.3 under D125–D128, for the generated notices, `licenses/` and the release inspection of the tarball and the examples' `dist/` trees, by session W5E under D176, for the compiled code's source maps, and D174, for the deck preview's overflow check, and by session W5P under D180, for the readable copies of the theme's minified stylesheets; amended by the security audit's remediation under D196, for `npm-shrinkwrap.json`. W5E's amendments and the remediation's were each revision 8 on their branch, and revision 9 was both; revision 10 is session RC's, for the rows of what stays out of the package once the application is the root of the papeleria repository.

This is the **planned** content of the npm package and of every generated `dist/`. It is a design record; the tests below hold the real trees to it. Since M1.8, `npm run test:package` packs the tarball, installs it for production in an empty folder, checks its file list against this table and makes, builds and checks a deck with it (D68), a report from M3.7 and a comic from M4.8. Since M5.3 it holds the tarball to an exact tree, tree by tree, with every notice and licence text byte for byte, and `test/integration/output-notices.test.ts` checks the notices of the four examples' `dist/` trees (D128). The release licence inventory is `docs/evidence/license-inventory.json` (D125, DEP06), and the third-party notices are generated: `THIRD_PARTY.md` and `licenses/` in the package (D126), and each `dist/`'s `THIRD_PARTY.md` (D127).

`files` in `package.json` is wired to this table. Entries that do not exist yet are listed deliberately so that the milestone which creates them does not have to remember to widen the list.

`sharp`, `libvips`, `html-validate`, `music-metadata`, the D3 modules and the CodeMirror packages are installed dependencies of the author's machine. The editor page that ships in `lib/clients/editor/editor.js` carries code from 58 package installations — CodeMirror, Lezer, `codemirror-json-schema`, shiki, `yaml` and others — so those are in `THIRD_PARTY.md` §3, with their own licence files in `licenses/packages/`, whichever `package.json` section lists them (D22, D33, D128). D41's locale definitions from d3-format and d3-time-format are copied into `lib/src/core/charts.js` (§2). The code of every other installed dependency stays out of the package tree; `THIRD_PARTY.md` lists them in §4 and §5 because npm installs them alongside it. Nothing from `sharp` or `libvips` reaches a published piece (PRD 13).

A deck or document `dist/` therefore names only own code and the two font families in `THIRD_PARTY.md`; a comic adds the page-turn engine. No author-machine dependency appears in a `dist/` inventory, because none of them is emitted.
